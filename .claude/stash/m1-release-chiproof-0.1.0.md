## Key decisions

Owner, 2026-08-30:

- `challengeSecret` is the config field name (borrowed from 8een).
- M1 implementation decisions recorded in spec §8: nonce store follows the
  8een pattern; signing is Ed25519 + canonical JSON; `bb verify` is invoked
  via an explicit `bbPath` pinned to 5.0.0; no spec negotiation in M1; the
  D20 seal means the HMAC covers every challenge field.
- **D25**: `zk-passport/1` ships tier-A-only as the genericity proof of the
  evidence slot; the nonce is carried in `service_subscope` (rule: first 31
  bytes of `sha256(nonce)` as a BN254 field element); the threshold is
  verified via a pinned Poseidon2 `param_commitment` table generated by the
  spike's Noir toolchain; the scope rule is ours, interoperable with
  zkPassport's derivation, with no code copied from it.
- **Q26**: tier B/C ZK needs a circuit with both a stable nullifier and a
  fresh nonce — this is Track Z's problem, not M1's.
- M2's row was moved to D24 evidence-set language.
- Q25 (whether the reference app ships bare or with `zk-passport/1`) is
  still open.
- Verdict shape carries `evidence:[types]` and an optional `warnings?`.
- Evidence bounds are enforced in the library itself, before any plug runs:
  duplicates refused, `maxItems` default 4, `maxItemBytes` default 256 KiB.
- `LIBRARY_CONVENTIONS` adopted; §7 exemption: `.claude/remember` and
  `.claude/stash` stay tracked (owner: dotfiles always are).
- NO-GO #7 reworded: no ZK circuits of ours; v1 is never described as
  zero-knowledge as a product; third-party ZK is only usable as an evidence
  plug, validation-grade, tier A.
- The publish workflow filename is `publish.yml` everywhere — the owner's
  npm trusted publisher binding is fixed to that name.

## Findings

1. The zkPassport age circuit's public inputs are `comm_in`,
   `current_date`, `service_scope`, `service_subscope` (it also returns
   `param_commitment`, `nullifier_type`, `nullifier`, `oprf_pk_hash`); there
   is no dedicated nonce input — `service_subscope` feeds `nullify()`, so a
   circuit is either challenge-bound OR a stable pseudonym, never both at
   once.
2. `bb verify` 5.0.0 measured at roughly 0.035 s sequential composition;
   plug verify 20–65 ms once stages are parallelised; a full re-prove is
   about 3.5 s per document.
3. Nonce binding is genuinely cryptographic: a re-proved proof fails
   against the old public inputs, verifies for the new nonce N, and is
   refused for a different N'.
4. The `dsc`/`id_data` verification keys differ between NL and US;
   `integrity`/`age` verification keys are identical across both — so the
   envelope needs a `vk_sha256` selector.
5. `@zkpassport/utils` declares no license (checked on npm and in the
   monorepo, verified via the GitHub API); the circuits repo itself is
   Apache-2.0.
6. Code review (medium effort): 5 findings including one HIGH — unbounded
   `evidence[]` amplification — all fixed.
7. `/security` scan: 0 findings.
8. `/clear` does NOT kill background agents — the orchestrator wrongly
   respawned a coder and the two raced; the fix is to check `ListAgents`
   first (saved to memory).
9. npm returns 404 on PUT when the OIDC trusted-publisher binding
   (repo/workflow filename) doesn't match; three failed publish runs were
   caused by the orchestrator naming the workflow `publish.yaml` after
   misreading a typo; renamed to `publish.yml` and it published immediately
   (saved to memory).
10. Publish-template validation, done by Sonnet: 8een's two extra CI steps
    are CI-proven and worth backporting with changes — use `prepack`
    instead of `prepublishOnly` plus a separate "Build types" step; the
    adopter-usability gate needs a per-repo quickstart (8een's heredoc is
    repo-specific, not portable as-is); move the skip-if-published check
    before the gate; drop the "mailproof" header line. Not applied anywhere
    yet — backporting this into the `hamr0` template repo is the owner's
    call.
