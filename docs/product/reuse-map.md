# Reuse map

One page for anyone lifting parts of zkagent into another project. zkagent is closed as a complete
experiment (D108); all of it is Apache-2.0 (see `LICENSE`, `NOTICE`). "Evidence" names what was
actually run, not what is plausible. Nothing here was independently audited. For lessons, not code,
read `docs/product/learnings.md`. Scanner paths are under
`apps/scanner/app/src/main/java/com/tananaev/passportreader/` (abbreviated `S/`); unit tests are
under `apps/scanner/app/src/test/java/com/tananaev/passportreader/`.

| Component | Path | What it does | Maturity and evidence | Depends on | Caveats for a lifter |
|---|---|---|---|---|---|
| Never-throw verdict core | `packages/chiproof/src/verdict.js`, `src/index.js` (`createVerifier`) | Verdict `{ok, allowed, reason}`; `ok:false` forces `allowed:null`, a real no is `ok:true, allowed:false`. Challenge issue/verify, single-use nonce spend, tier negotiation | Published (`chiproof@0.8.0` on npm); 191 unit/integration tests passed on 2026-10-24; exercised end to end by the reference scanner and demo on a Pixel 6a with two real documents | Nothing at runtime (Node 20+) | `InMemoryNonceStore` is test-only; you must supply a durable, atomic nonce store. No external adopter, no audit |
| Evidence-plug registry | `packages/chiproof/src/evidence.js`, `src/plugs/` (`attester-sig.js`, `signed-receipt.js`, `zk-passport.js`), `src/stores/attester.js` | Versioned registry; each plug declares what it binds and a linkability class and tier ceiling; plugs that throw become `ok:false`. Attester-key plugs (`sig-ed25519/1`, `sig-p256/1`) with trust-on-first-sight key binding | Same as above; planted-negative and alternatives-group tests in `packages/chiproof/tests/integration/` | Same | `zk-passport/1` verifies a third-party circuit via the external `bb` binary, tier A only; its e2e test skips without `bb`. The attester key comes from no configured trust source (TOFU only) |
| Chip read + government-signature check | `S/M0Probe.kt`, `S/MasterlistVerifier.kt`, `S/ChipAuthClassification.kt`, assets `DE_ML.ml`, `csca-germany-root.der` | Wraps JMRTD for BAC/PACE reads; verifies the SOD against the BSI masterlist, whose CMS signature chain is verified at load (corrupt list gives `ok:false`; a well-formed list lacking the issuer gives `ok:true, allowed:false` — the two-bucket rule); three-state chip-authentication result | Device-proven on a US passport (BAC) and an NL ID card (PACE) — `docs/logs/M0-EVIDENCE.md`, `M2-SCAN-EVIDENCE.md`, `M2-DEVICE-SESSION-2026-09-03-PM-EVIDENCE.md`; unit tests `MasterlistVerifierTest`, `PassiveAuthTrustTest`, `ChipAuthClassificationTest` | JMRTD, SCUBA, BouncyCastle (`bcpkix-jdk15on`, pinned old on purpose) | The bundled masterlist and root are a snapshot, not refreshed. The scanner derives from `tananaev/passport-reader`, which states Apache-2.0 but ships no LICENSE file (see `apps/scanner/NOTICE`) — resolve before redistributing. Two documents only: no coverage claim. Never hand-roll chip parsing |
| Device key with algorithm agility | `S/DeviceKey.kt`, `S/EvidenceSigner.kt`, `S/Canonical.kt` | Keystore/StrongBox P-256 (Ed25519 where available) attester key, per-origin; biometric-gated signing of the claim, nonce, scope and zktag | Device-proven on a Pixel 6a (`docs/logs/M2-SESSION-POC.md`); `EvidenceSignerTest` checks the byte layout against a vector produced independently in JS | AndroidX Biometric, AndroidKeyStore | Ed25519 is not available in `AndroidKeyStore` on the Pixel 6a; assert the returned algorithm. The "biometric" gate can be satisfied by a PIN. Keys die on uninstall |
| `LifecycleFence` | `S/LifecycleFence.kt` (+ `LifecycleFenceTest`) | Pure per-Activity-instance fence that drops a stale background-thread landing without cancelling in-flight work | 13 sites fenced in `MainActivity`; unit-tested; the BiometricPrompt site device-reproduced (findings #5, #16, `docs/logs/M2-FENCE-EVIDENCE.md`) | Nothing (pure Kotlin) | Enumerate sites by the hazard (a late framework callback touching Activity state), not by grepping `runOnUiThread` |
| `ReportLog` / `ReportLogStore` | `S/ReportLog.kt`, `S/ReportLogStore.kt` | Capped (20 entries), value-free scan log with collapse/expand; atomic JSON persistence in app-private storage that survives process death | Unit-tested (`ReportLogTest`, `ReportLogStoreTest`); persistence device-confirmed (Q38) | Nothing (pure Kotlin; Android file I/O in the caller) | Capped log evicts oldest, so never store policy state in it. "Clear log" was not device-exercised |
| `ThresholdPolicy` | `S/ThresholdPolicy.kt` (+ `ThresholdPolicyTest`) | Fixed preset list {15,16,18,21,60,65}; first-seen threshold locked per hostname; exact-hostname exception list | Device-confirmed (`docs/logs/M3-SCANNER-S1-EVIDENCE-2026-09-05.md`) | Nothing | The policy is pure; the lock map itself lives in `MainActivity.originThresholdLocks` and is persisted in the log store's file. Per-install: a reinstall resets it (disclosed) |
| `operator.json` build-time config | `apps/scanner/operator.json`, `apps/scanner/app/build.gradle.kts`, `S/OperatorPolicy.kt`, `apps/scanner/scripts/operator-json-negative.sh` | Gradle reads and validates a JSON file at configure time; a bad file fails the build loudly; values become `BuildConfig` fields read once at startup. The script runs 15 deliberately bad cases covering all nine validation rules, plus a restore check (16 `PASS` lines) | Device-verified 2026-09-06, released in v0.7.0/v0.7.1 (`docs/logs/M3-S67-POC-EVIDENCE-2026-09-06.md`); `OperatorPolicyTest` | Gradle, Kotlin | Schema and rules: `docs/wiki/milestones.md` §6.7. The negative script needs a built tree and Android SDK |
| `av://` + OpenID4VP `direct_post` handoff | `S/HandoffClient.kt`, `S/RequestTrust.kt`, `S/HandoffAdmission.kt`, `S/VerifierRefusal.kt`; verifier side `apps/demo/server.mjs`, `apps/demo/jws.mjs` | Same-device or QR link; request object fetched by reference and verified as an ES256 compact JWS (JAR); `client_id`/`request_uri`/`response_uri` must share one origin; a non-2xx `direct_post` is a refusal, never success | Device-proven end to end (`docs/logs/M3-POC-EVIDENCE-2026-09-04.md`, `M3-EXIT-ROWS-v0.6.0-2026-09-05.md`); a hostile second origin refused (finding #10); unit tests for each class | Android HTTP stack; Node for the verifier side | Only the local origin `http://127.0.0.1:8787` over `adb reverse` was proven; production well-known key discovery was never tested against a real TLS origin. The wire is OpenID4VP-shaped, not interoperable with real EU wallets (no mdoc, no issuer) |
| Demo verifier store | `apps/demo/store.mjs` (+ `tests/store.test.mjs`) | Flat JSON file with atomic temp-file-plus-rename writes for nonces, key bindings and seen-zktags; no in-memory fallback | Duplicate-zktag refusal survived a kill and restart on both documents (`docs/logs/M3-EXIT-ROWS-v0.6.0-2026-09-05.md`); 41 demo tests passed on 2026-10-24 | Node | Single-process, single-file; not concurrent-safe across processes |
| Headless wallet and tier-A diff | `apps/demo/scripts/fake-wallet.mjs`, `apps/demo/compare.mjs` | Plays the phone's role for roundtrip tests; per-field diff of two tier-A presentations | Used by the demo tests | Node | Its zktag in tier B is synthetic |
| npm publish workflow | `.github/workflows/publish.yml`, `ci.yml` | Manually dispatched npm trusted publishing over OIDC (no token), idempotent, asserts the end state; adopter type-check gate | Used for the `chiproof` releases (D72 lockstep); 0.8.0 is on the registry | GitHub Actions, npm | Adapted from the author's external `PUBLISH_TEMPLATE.yml` (not in this repo). The trusted publisher is bound to the exact filename `publish.yml`; never rename it. Verify a publish against the registry JSON, not the npm CLI cache |
| Evidence-doc process | `docs/logs/*-EVIDENCE*.md`, `docs/wiki/decisions.md`, `.claude/remember/findings.md` | Pre-registered pass/fail criteria, planted negatives with a paired non-vacuity pass, no PII (field names, counts, verdicts, timings only), retractions recorded | About 30 evidence docs across M0-M3 under `docs/logs/` | None | Process, not code. Real passport material never goes in git; keep fixtures gitignored |

**Not worth lifting as-is.** `MainActivity.kt` (about 3,900 lines; logic should live in the pure
classes above), `spikes/` (throwaway proofs of concept), `apps/demo/android` (an old dev test rig,
unbuilt and unverified on device, not the M2 scanner), and the zk-passport plug unless you want its third-party circuit.

**Before you reuse the whole.** Read `docs/wiki/backlog.md` (what is not built and how to rebuild
and run what is) and the NO-GO table in `docs/product/zkagent-prd.md` §9. This project describes
itself as captcha-grade, not zero-knowledge, and not certified for any legal age-verification duty.
